# NearPay embed protocol v1

Normative for `@nearpay/js`, the `js.<domain>/v1/nearpay.js` loader, `@nearpay/react` and the
checkout's `/embed/:id` page (`nearpay-checkout/src/routes/embed/protocol.ts`). Design:
`nearpay-brain/lld/checkout-and-js.md` §5.3 and §6. Machine-readable catalogue: [`v1.json`](v1.json).

## Envelope

Every message is a structured-clone object `{ "type": "np:<name>", "v": 1, ...payload }`.
Receivers ignore messages with another `type` prefix or another `v`, and tolerate unknown fields.

## Messages

| Direction | `type` | Payload |
|---|---|---|
| parent → iframe | `np:init` | `appearance: {theme: "light"\|"dark"\|"auto", accent: "#rgb"\|"#rrggbb"\|null, radius: 0–24\|null}`, `locale: string\|null` |
| iframe → parent | `np:ready` | — |
| iframe → parent | `np:resize` | `height` (CSS px, integer) |
| iframe → parent | `np:complete` | `session_id` (`cs_…`), `payment_intent_id` (`pi_…`, the session's `payment_intent`; `null` only from checkouts built on `@nearpay/spec` < 0.1.5) |
| iframe → parent | `np:error` | `code`, `message` |
| iframe → parent | `np:close` | — |

## Origin rules

- The parent creates `<iframe src="<PAY_ORIGIN>/embed/<cs_id>#<client_secret>"
  sandbox="allow-scripts allow-same-origin allow-popups allow-forms" allow="clipboard-write">`.
  The client secret travels only in the fragment.
- The parent posts `np:init` with `targetOrigin = PAY_ORIGIN` (never `"*"`), on the frame's `load`
  event and again every 250 ms until `np:ready` (at most 40 times): the frame may not be listening yet.
- The parent accepts a message only when `event.origin === PAY_ORIGIN` **and**
  `event.source === iframe.contentWindow`.
- The iframe accepts `np:init` only from `window.parent`, only when `event.origin` is one of the
  session's `allowed_origins` and, where the browser exposes it, `location.ancestorOrigins[0]` is the
  same origin. A parent that fails the check is blocked at once and receives nothing. After a verified
  `np:init` every iframe → parent message is posted to that origin only.
- `np:complete` is delivered at most once per mount.

## Versioning

A breaking change ships as `v: 2` together with a new loader path (`/v2/nearpay.js`); `/v1/` keeps
speaking v1. Additive payload fields stay in v1.
